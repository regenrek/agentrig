# Registry overview

AgentRig separates **installable registries** from **discovery surfaces**.

The directory answers **what exists**.
The registry answers **what may be installed**.

## Core pieces

- **Official registry** - hosted at `https://agentrig.ai/registry`.
- **Third-party registries** - static signed registries that implement the same contract.
- **Directory** - a curated discovery index at `https://agentrig.ai/directory/index.json`.
- **Submissions** - review and discovery inputs that can later be mirrored into an installable registry.

## Install contract

Public installation is allowed only from static signed registries.

Canonical install refs use:

```text
<registryAlias>/<namespace.plugin>
```

The unversioned form resolves to the registry's latest installable version.
Append `@<version>` only when you need an exact reproducibility or rollback pin.

Canonical ids use:

```text
namespace.plugin
```

Direct URLs, local files, ZIP uploads, author repos, and Convex-hosted bytes are **not** installable public sources.

## Version and integrity records

Registry histories expose `latest_version`, `active_version`, and immutable
version records. During install, AgentRig resolves the requested latest or pinned
version, validates the registry source/lock/review artifacts, and records the
concrete version plus `snapshot_digest` in the local install ledger.

Plugin artifacts are the normal V1 distribution path. Standalone skill artifacts
can also be installed directly:

```bash
agentrig skill install <provider> <registryAlias>/<namespace.skill>
```

Standalone MCP and hook installs without `--pick` are not a public V1 flow;
install MCPs and hooks as plugin contents.

## Discovery contract

The directory and submission surfaces may:

- show external projects
- show `listed` entries
- link to upstream repos
- offer submit-for-review workflows

They must not imply install trust.

Use the pages in this section to host your own registry, understand trust tiers, and get listed in the directory.
