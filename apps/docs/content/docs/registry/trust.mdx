# Trust tiers

AgentRig assigns trust at the registry artifact level. Discovery metadata and author identity stay separate from install trust.

| Tier | Source | Behavior |
| --- | --- | --- |
| `official` | Official AgentRig registry artifact | Installable. |
| `reviewed` | Reviewed registry artifact that satisfies the canonical contract | Installable. |
| `listed` | Discovery listing only | Not installable. |
| `blocked` | Hard-blocked artifact | Not installable. |
| `yanked` | Historical or advisory-only artifact | Not installable for new installs. |

## How trust is determined

- Trust applies to published registry artifacts, not to arbitrary sources.
- Only static signed registries can publish installable `official` or `reviewed` entries.
- Directory presence can at most produce `listed`, which is discovery-only.
- Direct URLs, ZIPs, author repos, and Convex-hosted bytes are outside the install contract.

## Identity is orthogonal

`verified-author` is **not** a trust tier.

It is identity or ownership metadata only and must never be used to imply installability.

## Discovery versus install

- Discovery may show `listed` projects, external repos, and submit-for-review flows.
- Discovery must not present the same install CTA as `official` or `reviewed`.
- Install trust comes from signed registry state plus digest verification, not from directory or profile metadata.
