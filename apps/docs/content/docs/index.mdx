# Agentrig documentation

Agentrig helps devs and teams package the AI workflows that already work, then reuse them across projects, tools, and teams.
Instead of rebuilding the same setup for every repo or assistant, you can author it once as plugins, compose it into rigs, and install it natively where people already work.

<Callout title="What is a plugin?">
A plugin is a folder with `.plugin/plugin.json` plus the files you want to install (skills, scripts, hooks, agents, MCP, and more).
AgentRig plugin manifests are [Open Plugins 1.0.0](https://open-plugins.com/plugin-builders/specification) conformant, with AgentRig-specific fields under `x-agentrig`.
The CLI's public install contract is the AgentRig `InstallBundle` resolved from
approved marketplace listings.
</Callout>

## How AgentRig helps

![How Agentrig standardizes and reuses AI workflows across projects and tools](/agentrig_explanation.jpg)

Agentrig is not limited to one assistant or editor.
You can export and install the same plugin as a native integration for the tools many developers already work in every day.

- **Reusable workflow plugins:** package skills, MCP config, hooks, agents, commands, and rules into marketplace-installable plugins that can be shared across projects.
- **Composable rigs for teams:** combine plugins into shared setups for a stack, repo, or org so teams can standardize how they work with AI.
- **Native delivery where people work:** export the same workflows as integrations for [Claude Code](/integrations/claude-code), [Codex](/integrations/codex), and [Cursor](/integrations/cursor), with tracked installs and safer cleanup.

See [Marketplace exports](/integrations/marketplace) for provider-native output layouts and [Rigs](/rigs) for team composition.
