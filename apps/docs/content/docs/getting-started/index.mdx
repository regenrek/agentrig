# Getting started

AgentRig starts with a simple consumer flow:

1. initialize config
2. browse available plugins
3. inspect a plugin if needed
4. install it as a native provider plugin

## Official registry flow

<Steps>
  <Step>
    <h3>Install agentrig</h3>
    <p>Install the CLI once so you can use the same plugin workflow in any repo.</p>

    ```bash
    npm install -g agentrig
    ```
  </Step>
  <Step>
    <h3>Initialize config</h3>
    <p>Seed a minimal config with the official registry.</p>

    ```bash
    agentrig init
    ```
  </Step>
  <Step>
    <h3>Browse the official registry</h3>
    <p>See what plugins are available before you install anything.</p>

    ```bash
    agentrig list --available
    ```
  </Step>
  <Step>
    <h3>Inspect the plugin</h3>
    <p>Optional, but useful if you want to review dependencies, files, and trust before installing.</p>

    ```bash
    agentrig view agentrig/agentrig.core-committer
    ```
  </Step>
  <Step>
    <h3>Install it as a provider plugin</h3>
    <p>Choose the provider you actually use in Claude Code, Codex, or Cursor.</p>

    ```bash
    agentrig plugin install codex agentrig/agentrig.core-committer
    ```
  </Step>
</Steps>

## Third-party registry flow

Third-party registries are explicit.
Add the registry first, then install plugins from it with the canonical install ref:

`<registryAlias>/<namespace.plugin>`

The unversioned form installs the latest installable version. Add `@<version>`
only when you need an exact reproducibility or rollback pin.

```bash
agentrig registry add georg https://georg.dev/agentrig
agentrig list --available --registry georg
agentrig plugin install cursor georg/georg.ts-master-plugin
```

## What is not installable

- direct `.plugin/plugin.json` URLs
- local file paths as public install refs
- ZIP uploads
- author repos
- arbitrary HTTPS manifest URLs
- Convex-hosted bytes

Use those surfaces for authoring, review, or discovery only. Public installs come from static signed registries.
