# CLI overview

The CLI installs full plugin bundles, installs selected artifacts from those
bundles, manages registry aliases, and applies rigs.
Run `agentrig --help` for global help.

## Common commands

- `agentrig init` - create config file.
- `agentrig list --available` - browse available plugins.
- `agentrig view <registryAlias>/<namespace.plugin>` - inspect the latest plugin version before installing.
- `agentrig plugin install <provider> <registryAlias>/<namespace.plugin>` - install the full latest plugin bundle.
- `agentrig install <provider> <registryAlias>/<namespace.plugin> --pick skill:<name>` - install selected skills, MCPs, or hooks from a plugin as a Selection Bundle.
- `agentrig skill install <provider> <registryAlias>/<namespace.skill>` - install a standalone skill artifact.
- `agentrig plugin uninstall <provider> <registryAlias>/<namespace.plugin>` - remove a provider plugin.
- `agentrig skill uninstall <provider> <registryAlias>/<namespace.skill>` - remove an AgentRig-managed standalone skill install.
- `agentrig rig apply <provider> <rig>` - apply an advanced rig.
- `agentrig registry add` - add a registry.
- `agentrig plugin init` - scaffold a new plugin.

Public installs use latest-first marketplace refs:
`<registryAlias>/<namespace.plugin>` for plugins and
`<registryAlias>/<namespace.skill>` for standalone skills. Add `@<version>` only
when you need an explicit reproducibility or rollback pin. Install ledgers still
record the concrete resolved version and snapshot digest, even when the command
uses the unversioned latest ref. Install commands resolve refs by fetching an
AgentRig `InstallBundle` from `agentrig.ai`.

Plugin install remains the primary full-bundle path. Selection install is the
selective path for choosing specific artifacts from an installable marketplace
plugin. In V1, standalone MCP and hook installs without `--pick` are not a
public flow; install MCPs and hooks as plugin contents with `--pick`.
