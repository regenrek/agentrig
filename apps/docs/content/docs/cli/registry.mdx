# `agentrig registry`

Manage the registries in your config file.

The official registry is seeded by `agentrig init`.
Third-party registries are explicit: add the registry first, then install plugins
from it with `<registryAlias>/<namespace.plugin>`. Add `@<version>` only when
you need an exact reproducibility or rollback pin.

## List registries

```bash
agentrig registry list
```

## Add or update a registry

```bash
agentrig registry add georg https://georg.dev/agentrig
```

After adding a registry:

```bash
agentrig list --available --registry georg
agentrig plugin install codex georg/georg.ts-master-plugin
```

Registry aliases are for static signed registries only. Direct URLs, local files, ZIP uploads, and author repos are outside the public install contract.

Unversioned refs resolve to the registry's latest installable version. The
install ledger records the concrete resolved version and snapshot digest, so
uninstall and repair stay deterministic.

`agentrig inspect <repo>` and `agentrig use <repo>` are separate external-repo workflows.
They can scan and reuse selected files, but they must not be added as registry aliases and
must not be described as public registry installs.

AI does not change this boundary. CLI enrichment is local BYOK only, and web-hosted
enrichment produces draft fields that require admin acceptance before they can enter
a submitted manifest.

## Options

- `--cwd <path>` - working directory.
- `--global` - write to global config.

## Notes

- Registry aliases use lowercase letters, numbers, and hyphens.
- Registry URLs must point at a base URL that serves `registry.json` at the root.
- Use `--global` when you want a registry available across repos instead of only in the current project.
