# Marketplace exports

Use `agentrig plugin export` when you are authoring local plugins and want provider-native marketplace output.

Consumers do not need this command for normal installs.
They should use:

```bash
agentrig plugin install <provider> <plugin-spec>
```

For public installs, `<plugin-spec>` must be the canonical registry ref
`<registryAlias>/<namespace.plugin>`. Add `@<version>` only when you need an
exact reproducibility or rollback pin.

## How export works

![How AgentRig converts plugins into native plugins and tracks installs safely](/agentrig_plugin.jpeg)

- Start with an AgentRig plugin as the portable source of truth for prompts, assets, scripts, MCP config, and other workflow files.
- `agentrig plugin export` converts that plugin into each provider's native plugin marketplace layout for Claude, Codex, or Cursor.

```bash
agentrig plugin export --agent all --pluginsDir registry/plugins --out dist/plugins
```

Export a single plugin:

```bash
agentrig plugin export --agent all --plugin acme.my-plugin --pluginsDir registry/plugins --out dist/plugins
```

This generates:

```text
dist/plugins/
  claude/
  codex/
  cursor/
```

Each provider gets its own native layout:

- `claude`: `.claude-plugin/marketplace.json` plus `plugins/<plugin>/.claude-plugin/plugin.json`
- `codex`: `.agents/plugins/marketplace.json` plus `plugins/<plugin>/.codex-plugin/plugin.json`
- `cursor`: `.cursor-plugin/marketplace.json` plus `plugins/<plugin>/.cursor-plugin/plugin.json`

## Optional config file

Create `agentrig.plugins.json` to customize output:

```json
{
  "pluginPrefix": "agentrig-",
  "owner": { "name": "Agentrig", "email": "team@agentrig.ai" },
  "providers": {
    "claude": {
      "marketplaceName": "agentrig-community"
    },
    "codex": {
      "marketplaceName": "agentrig-local",
      "displayName": "Agentrig Local"
    },
    "cursor": {
      "marketplaceName": "agentrig-marketplace"
    }
  },
}
```

The exporter reads this file automatically when present.
