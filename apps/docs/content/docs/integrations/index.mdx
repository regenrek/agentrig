# Integrations

AgentRig can take a resolved plugin and install it as a native plugin for:

- `Claude Code`
- `Codex`
- `Cursor`

## Consumer flow

```bash
agentrig plugin install <provider> <registryAlias>/<namespace.plugin>@<version>
agentrig plugin uninstall <provider> <registryAlias>/<namespace.plugin>@<version>
```

Use `plugin install` for the full bundle. Use selection install when you only
want specific skills, MCPs, or hooks from that bundle:

```bash
agentrig install <provider> <registryAlias>/<namespace.plugin>@<version> \
  --pick skill:<name> \
  --pick mcp:<name>
```

Selection install materializes an AgentRig-managed Selection Bundle. The
provider receives only the selected artifacts that pass SDK closure checks.

Public install refs are exact and registry-only:

- `agentrig/agentrig.core-committer@0.1.0`
- `georg/georg.ts-master-plugin@1.2.0`

Direct `.plugin/plugin.json` paths, arbitrary URLs, ZIPs, and author repos are outside the public install contract.

## Author flow

If you are publishing or testing local plugins, export provider-native marketplaces from plugin directories:

```bash
agentrig plugin export --agent <provider|all> --pluginsDir registry/plugins
```
