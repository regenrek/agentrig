# Official registry workflow

Contributions are welcome! You can:

- Add or update a plugin in the canonical registry layout
- Add a registry to the discovery directory

If you already used the submission flow in AgentRig, the destination is still the same:
an approved submission opens or updates a PR into `agentrig-registry`, and the
version becomes publicly installable only after that PR is merged.

Discovery submissions created from pasted repo URLs or `agentrig inspect` output are
not installable. They help reviewers find candidate files and metadata, but a registry
version still needs the canonical source, lock, review, README, license, and plugin
manifest artifacts below.

AI-enriched text is also discovery-only until accepted by an admin. In v1, hosted AI
enrichment exists only in the web submit flow and is gated by login, Turnstile, quotas,
and review. The CLI supports only local BYOK enrichment, where the user's provider key
is sent directly to their configured provider and never to AgentRig.

## Add a plugin

1. Create or update `plugins/<namespace>/<plugin>/plugin.json`.
2. Add a version at `plugins/<namespace>/<plugin>/versions/<version>/`.
3. Include `.plugin/plugin.json`, `AGENTRIG_SOURCE.json`, `AGENTRIG_LOCK.json`, `AGENTRIG_REVIEW.json`, `README.md`, and `LICENSE`.
4. Run the validator:

```bash
node scripts/validate-registry.mjs --write
node scripts/validate-registry.mjs --check
```

5. Open a PR against `agentrig-registry`.

## Rules

- Do not add compatibility shapes, aliases, or fallback metadata.
- Do not publish installable artifacts from Convex, ZIP uploads, author repos, or arbitrary URLs.
- Do not treat external-repo installs, discovery submissions, or AI-enriched draft text as registry trust.
- The canonical path is:
  - `registry.json -> plugins/<namespace>/<plugin>/plugin.json -> versions/<version>/...`
- The canonical install ref is:
  - `<registryAlias>/<namespace.plugin>` by default
  - `<registryAlias>/<namespace.plugin>@<version>` only when an exact pin is needed

## Add a registry to the directory

Add a discovery entry following the directory schema. Directory presence is discovery-only and does not grant install trust.

Directory updates are Git-based, not uploads.

## Keep changes safe

- Keep all required version artifacts present and aligned.
- Keep trust tier, installability, and advisory state internally consistent.
- Keep discovery terms separate from install terms.
