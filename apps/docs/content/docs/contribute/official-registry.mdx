# Official registry workflow

Contributions are welcome! You can:

- Add a plugin under `plugins/<name>/<version>`
- Add a registry to the directory at `apps/docs/public/directory/index.json`

## Add a plugin

1. Create `plugins/<plugin-id>/<version>/` and add `.plugin/plugin.json`.
2. Update `manifests/<plugin-id>.json`.
3. Update `registry.json`.
4. Run the registry build to refresh derived delivery output.
5. Open a PR.

## Hard cut

- Do not add committed root `<pluginId>.json` files to the registry source repo.
- Do not add fallback discovery shapes or compat shims.
- The canonical source registry path is:
  - `registry.json -> manifests/<id>.json -> paths.plugin -> plugins/<id>/<version>/.plugin/plugin.json`
- Any expanded `files[]` or optional `sha256` metadata belongs in the derived `.plugin/install.json` build artifact only, not in committed source metadata.

## Add a registry to the directory

Edit `apps/docs/public/directory/index.json` and add a new entry following the directory schema.

This file is served by the docs app at `/directory/index.json`. Directory updates are Git-based (PR + deploy), not uploads.

## Keep changes safe

- Keep `.plugin/plugin.json` valid and version-aligned with its directory.
- Keep `manifests/<id>.json` and `registry.json` aligned with the plugin path.
